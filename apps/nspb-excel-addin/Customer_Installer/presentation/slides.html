● NSPB Copilot 04 / 12 — Beyond MCP

What makes it more than a tool gateway.

MCP exposes tools. A copilot composes them — and works around their failures.

Vanilla MCP NSPB Copilot
Tool execution ✓ single tool per turn ✓ multi-tool orchestration · auto-retry on Pro after Flash MALFORMED
Tenant grounding ✗ stateless tools — no notion of this client ✓ per-tenant KB + live discovery — answers reference YOUR cubes/forms/rules verbatim
Routing intelligence ✗ always same model ✓ Flash for concepts (5s) · Pro for implementation (12s) · explicit EXPLAIN MODE for FAQ
Conversation flow ✗ Q → A → end ✓ chip-driven follow-ups · zoom_in / zoom_out / keep_only over the active grid · contextual
Persistence ✗ session-scoped ✓ 4-tier durable settings (Office / local / IndexedDB / hidden Excel sheet) · form cache survives forever
Hallucination control ✗ model-dependent ✓ tenant facts in prompt · explicit "use only listed names" rule · client-side intercepts for cubes/dims (zero AI)
Excel integration ✗ chat only ✓ writes grids to sheets · paints editable cells · keeps SmartView format · multimodal (paste images)
Onboarding ✗ manual config per user ✓ one button "Load everything" — imports JSON, discovers REST, pre-caches 150 forms, writes report

The copilot is the orchestration layer over MCP — not a replacement.

MCP gives the model hands. The copilot gives it eyes (active sheet), memory (per-tenant facts), routing (Flash vs Pro), and a UI (chips, intent tree, slash menu) that turns conversational AI into something an FP&A user can trust on a Tuesday afternoon.

● NSPB Copilot 05 / 12 — Anatomy of a response

What happens between the keystroke and the answer.

9 stages, all measurable. End-to-end ~5–15 seconds.

1
Client
Capture & route. Input typed → check slash menu → check intent regex → decide which intercept handles it. Some commands never hit AI: show me the cubes, set variable X, open form Y.
0 ms
2
Client
Auto-classify. If the question starts with How / What / Why / When → flag forceExplain=true. If it's an action verb (analyze, compare) → leave tools enabled.
+1 ms
3
Client → Worker
POST /api/chat. Body carries: messages, settings (host/user/pwd), tenantKb, appConfig, activeSheet (if any), lastGrid, the forceExplain flag.
+50 ms
4
Worker
Build prompt. Stitch KB.md + TENANT FACTS (cubes, dims, vars, sample forms/rules) + active sheet context + tools schema. EXPLAIN MODE uses a slim KB-only prompt.
+5 ms
5
Worker
Pick model. Concept → Flash (5s). Implementation/analysis → Pro (12s). Routing decided per turn from the question text.
+1 ms
6
Worker → Gemini
Call AI. Gemini reads the prompt, decides: prose answer OR call a tool (analyze_active_sheet, build_adhoc, open_form, …). Returns either text or tool args.
+3–12 s
7
Worker
Tool dispatch. If tool requested: hit NSPB REST / SmartView XML → parse → return result back to AI for narration. Loop up to 6 turns.
+0.5–3 s
8
Worker → Client
Compose response. Send back: prose reply + grids (to write to Excel sheets) + chip hints + grid descriptor (for next-turn modify_grid).
+50 ms
9
Client
Render. Write grids to Excel via Office.js (yellow cells for input forms). Render bubble + clickable chips. Persist evolved grid descriptor for next turn.
+200 ms

● NSPB Copilot 08 / 12 — KB & prompt assembly

How the AI sees your tenant on every turn.

The system prompt is built fresh per request — fused KB + tenant + live state.

Prompt assembly per turn

// EXPLAIN MODE (concept questions) SYSTEM: STRICT EXPLAIN rules (no tools) + KB.md (~ 175 KB) + TENANT FACTS: - cubes: NSP_NFS, Workforc, Report - scenarios: NSP_Actual, NSP_Forecast, NSP_Budget - vars: NSP_PER_RptCurrMo, … - sample forms: OpEx by Dept., … - "DO NOT invent FY33, Louisiana" // FULL MODE (action / data questions) SYSTEM: routing rules + tools schemas (build_adhoc, open_form, …) + CATALOG (cube → dims) + TENANT INVENTORY: - all 162 forms (with descriptions) - all 89 rules - all 41 vars (with current values) - navigation flows + active sheet (if any) + last grid descriptor USER: messages history

~280 KB total in full mode → with implicit prompt caching, ~75 % discount on subsequent turns within 5 min.

Anti-hallucination layers

  • Layer A — Tenant facts always wins. The prompt explicitly says: "Use ONLY names from TENANT FACTS. Do NOT invent."
  • Layer B — Client intercepts. Common queries (show me the cubes, show dimensions) bypass the AI entirely. Zero hallucination, zero latency, zero cost.
  • Layer C — Tool dispatch. Real numbers come from REST tools, not from the AI's memory. The AI narrates what the tool returned, not what it imagined.
  • Layer D — Pro for implementation, Flash for concept. Implementation questions route to Pro because Pro follows the strict rules better.
  • Layer E — Chip-driven flow. Follow-up chips are pre-formatted with EXACT names from inventory, so users keep the conversation on real ground.
